### Backwards-incompatible changes

- Semaphore only accepts broadcast messages from the GitHub repositories listed in the new `SEMAPHORE_GITHUB_REPOS` environment variable, a comma-separated list of `owner/repo` names. Forks are rejected even if they are listed. Pushes from other repositories are acknowledged, ignored, and logged as a warning, and other repositories that the GitHub App can see are skipped with a warning when Semaphore loads broadcasts at startup. `SEMAPHORE_GITHUB_REPOS` must be set to use the GitHub App: if the GitHub App credentials are set but the list is unset or empty, the GitHub App is disabled.

### Bug fixes

- Semaphore publishes broadcasts from pushes to a repository's actual default branch, rather than from pushes to a branch named `main`. Pushes to other branches, including `main` when it isn't the default branch, are ignored.
- Pushes that delete a branch are ignored.
- A GitHub webhook payload without an `installation.id` gets the intended error response instead of raising an unhandled exception.
- A malformed broadcast file no longer stops Semaphore from starting. When Semaphore loads broadcasts at startup, such a file is skipped with a warning and the other files and repositories are still loaded.
- When Semaphore loads broadcasts at startup, it reads every page of the repositories that the GitHub App installation can see, rather than only the first page.

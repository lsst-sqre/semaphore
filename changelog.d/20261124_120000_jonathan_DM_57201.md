### Bug fixes

- If GitHub fails or can't be reached while Semaphore processes a push to a broadcast repository, Semaphore keeps serving the broadcasts it couldn't read, including those from the old default branch on the first push after the default branch changes, and reloads the repository in the background once GitHub recovers, with the same backoff as at startup. Before, Semaphore ignored the push, or the files that GitHub failed to return, and the repository's broadcasts stayed out of date until the next push or restart, since GitHub doesn't redeliver failed webhooks on its own. The push is still acknowledged with a 202 response.
- A repository that fails to load at startup, or that fails while a push is processed, is reloaded in full from its current default branch. A broadcast whose file was deleted meanwhile stops being served, and a repository whose default branch changed meanwhile serves one copy of each broadcast, from the new default branch.

### Bug fixes

- If GitHub fails or can't be reached while Semaphore lists the installations of its GitHub App at startup, for example with a server error, a connection error or an authentication error, Semaphore still starts, rather than crash-looping. It logs a warning, keeps the broadcasts of the installations on the pages that GitHub returned before it failed, and lists the installations again in the background, with a new app token for each attempt and the same backoff as other retries. Once GitHub returns the whole listing, Semaphore loads each installation, skipping the same installations as at startup, and serves their broadcasts without a restart or a push. Semaphore doesn't log the warning about allowed repositories that no installation can see until it has listed the installations and tried to load each one.

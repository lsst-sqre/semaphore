### Bug fixes

- If GitHub fails or can't be reached while Semaphore loads broadcasts at startup, for example with a server error, a timeout, an exceeded rate limit or an authentication error, Semaphore still starts. It logs a warning and keeps retrying the affected repositories in the background, waiting longer between attempts up to five minutes, until each one loads. Their broadcasts are then served without a restart. Each Semaphore replica retries on its own. The summary that Semaphore logs after loading broadcasts at startup reports the number of these repositories as `failed_repo_count`.
- A source repository with no `broadcasts` directory no longer stops Semaphore from starting. It's loaded as a repository with no broadcasts, without a warning.
